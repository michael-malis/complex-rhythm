## R-PROC-002. Единый реестр TASKS.md

Создай `TASKS.md`.

Файл является единственным авторитетным реестром состояния выполнения.

Для каждой задачи обязательны следующие поля:

| Поле | Содержание |
|---|---|
| ID | Постоянный уникальный идентификатор |
| Requirement | ID исходного требования |
| Parent | Родительская задача |
| Action | Точное действие |
| Dependencies | Предварительные условия |
| Deliverable | Конкретный результат |
| Acceptance | Критерии PASS/FAIL |
| Status | Текущее состояние |
| Evidence | Доказательства |
| Defects | Связанные ошибки |
| Commit | Git-коммит выполнения |

Допустимые статусы:

- `TODO`
- `IN_PROGRESS`
- `BLOCKED`
- `FAILED`
- `VERIFIED`

Другие статусы запрещены.

В частности, запрещены:

- `ALMOST_DONE`
- `MOSTLY_DONE`
- `GOOD_ENOUGH`
- `PARTIALLY_COMPLETE`
- `ASSUMED_COMPLETE`

Родительская задача имеет статус `VERIFIED` только тогда, когда все обязательные дочерние задачи имеют статус `VERIFIED` и пройдена проверка интеграции родительской функции.

## R-PROC-003. Двусторонняя прослеживаемость

Создай `TRACEABILITY.md`.

Для каждого требования зафиксируй:

`Requirement ID → Task IDs → Implementation → Tests → Evidence → Status`

Для каждой задачи зафиксируй обратную связь с исходным требованием.

Добавь автоматизированную проверку реестра.

Проверка обязана обнаруживать:

- Требования без задач.
- Задачи без требований.
- Дублирующиеся ID.
- Отсутствующие зависимости.
- Ссылки на несуществующие задачи.
- `VERIFIED` без доказательств.
- Завершённые родительские задачи с незавершёнными дочерними.
- Требования без критериев приёмки.

**PASS:** автоматическая проверка возвращает ноль нарушений.

## R-PROC-004. Неизменный протокол исполнения задачи

Для каждой задачи выполняй последовательность:

1. Определи следующую доступную задачу с учётом зависимостей.
2. Переведи её в `IN_PROGRESS`.
3. Реализуй требуемые изменения.
4. Выполни локальные тесты.
5. Выполни интеграционные тесты, если задача влияет на другие компоненты.
6. Зарегистрируй найденные дефекты.
7. Исправь их.
8. Повтори тесты.
9. Сохрани доказательства.
10. Присвой `VERIFIED` только после полного PASS.
11. Обнови реестр.
12. Зафиксируй изменения в Git.
13. Автоматически перейди к следующей доступной задаче.

Не запрашивай дополнительное разрешение на уже предусмотренную работу.

Каждый дефект должен иметь отдельную запись.

Запись содержит:

- Влияние на требования.
- Задачу исправления.
- Результат повторной проверки.

Если дефект обнаружен в ранее проверенной функциональности, связанные задачи возвращаются в `FAILED` до исправления и повторной проверки.

**Запрещено сохранять статус `VERIFIED` после доказанного нарушения соответствующего критерия приёмки.**

- Проведённые проверки.

Работай в существующем репозитории.

Используй отдельные логически обоснованные коммиты.

После проверки задачи обновляй `TASKS.md` и сохраняй соответствующий результат в Git.

Запрещено:

- Удалять существующую историю.
- Использовать destructive reset для сокрытия изменений.
- Выполнять force push без необходимости, предусмотренной существующим процессом проекта.
- Перезаписывать чужие незакоммиченные изменения.
- Объявлять коммит проверенным, если соответствующие тесты не выполнялись.

После завершения всех проверок отправь изменения в существующий удалённый репозиторий, если доступ и права позволяют это сделать.

При отсутствии доступа зафиксируй `BLOCKED`, причину и конкретную неподтверждённую операцию.

# 17. НЕЗАВИСИМАЯ ЗАКЛЮЧИТЕЛЬНАЯ РЕВИЗИЯ

Для каждого `R-*`:

2. Проверь фактическую реализацию.
3. Проверь тесты.

# 19. ИТОГОВЫЙ АЛГОРИТМ ЗАВЕРШЕНИЯ

Исполнитель обязан применить следующий алгоритм:

```text
READ ENTIRE SPECIFICATION

CREATE COMPLETE REQUIREMENT INVENTORY

DECOMPOSE EVERY REQUIREMENT

CREATE TASKS.md

CREATE TRACEABILITY.md

VALIDATE 100% REQUIREMENT COVERAGE

IF COVERAGE != 100%:
    FIX TASK REGISTRY
    DO NOT START IMPLEMENTATION

FOR EACH AVAILABLE TASK:
    SET STATUS = IN_PROGRESS

    IMPLEMENT REQUIREMENT

    RUN REQUIRED TESTS

    IF TESTS FAIL:
        SET STATUS = FAILED
        REGISTER DEFECTS
        IMPLEMENT FIXES
        RERUN TESTS

    IF EXTERNALLY BLOCKED:
        SET STATUS = BLOCKED
        RECORD EVIDENCE
        CONTINUE INDEPENDENT TASKS

    IF ALL ACCEPTANCE CONDITIONS PASS:
        RECORD EVIDENCE
        SET STATUS = VERIFIED
        UPDATE TASKS.md
        COMMIT VERIFIED WORK

    RECHECK DEPENDENT REQUIREMENTS

AFTER ALL TASKS:
    REREAD ORIGINAL SPECIFICATION
    REBUILD TRACEABILITY CHECK
    RUN COMPLETE TEST SUITE
    INSPECT FINAL UI
    VERIFY MATHEMATICS
    VERIFY AUDIO
    VERIFY PRESETS
    VERIFY GIT STATE

IF ANY REQUIRED TASK != VERIFIED:
    RESULT = NOT COMPLETE
ELSE IF ANY ACCEPTANCE GATE != PASS:
    RESULT = NOT COMPLETE
ELSE IF ANY UNREGISTERED REQUIREMENT EXISTS:
    RESULT = NOT COMPLETE
ELSE IF ANY KNOWN CRITICAL DEFECT EXISTS:
    RESULT = NOT COMPLETE
ELSE:
    RESULT = COMPLETE

WRITE FINAL_REPORT.md
```

**Запрещено изменять этот алгоритм таким образом, чтобы непроверенная или заблокированная задача могла получить статус полного завершения.**
